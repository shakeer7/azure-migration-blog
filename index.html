2. Phase 1: Discovery & Assessment (From Scratch)

Before moving a single byte, you must understand your current estate. This phase minimizes risk and ensures no critical dependencies are broken.

  • Stakeholder Alignment: Define business goals, RTO/RPO requirements, and compliance needs.
  • Inventory Discovery: Deploy the Azure Migrate Appliance to discover all physical/virtual servers.
  • Dependency Mapping: Map communications between servers to group applications into "migration waves."

4. Phase 3: Azure Landing Zone Setup

An Azure Landing Zone is the foundational environment that hosts your workloads. You must build this *before* migrating applications.

Deploy the Hub VNet (with Azure Firewall and VPN Gateway) and Spoke VNets via VNet Peering.

Setup Microsoft Entra ID, configure MFA, and deploy Microsoft Defender for Cloud for Zero Trust.

Apply Azure Policies to restrict regions and deploy Log Analytics Workspaces for Azure Monitor.

5. Phase 4: The 5 R's of Migration Strategy

Rehost (Lift & Shift)

Use Azure Migrate to replicate VMs exactly as they are (IaaS). Fast and reliable.

Refactor

Slight modifications to leverage PaaS (e.g., local SQL to Azure SQL Managed Instance).

Rearchitect

Modify and extend application code base to optimize for cloud scale.

Rebuild

Rewrite the app using cloud-native technologies (AKS, Azure Functions).

Replace

Retire the custom app and move to a SaaS solution (e.g., Office 365).

6. Phase 5: Execution, Testing & Cutover

  • Replication: Start initial data sync using Azure Site Recovery (ASR). Runs in background without impact.
  • Test Migration: Perform failover test in an isolated VNet to validate app functionality.
  • Final Cutover: Final delta sync, shutdown on-prem, update DNS, and power on Azure VMs.

7. Phase 6: Post-Migration Optimization

Migration is not the end. Continuously review Azure Advisor recommendations to downsize over-provisioned VMs and secure workloads.
